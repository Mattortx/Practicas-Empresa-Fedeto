# 2. Contexto de empresa, proceso y problema a resolver

## Contexto de empresa

Protecciones Toledo S.L. trabaja en soluciones metálicas de protección para trabajos en altura. Su actividad está vinculada a sectores como construcción, mantenimiento industrial, cubiertas, obra civil, instalaciones técnicas, rehabilitación y entornos con riesgo de caída.

Las familias comerciales contempladas en el proyecto son:

- Protección provisional de borde.
- Protección definitiva de borde.
- Bases y casquillos.
- Auxiliares para la construcción.
- Consumibles.
- Soluciones a medida.
- Documentación o consultas técnicas sensibles.

El cliente tipo no es un usuario doméstico, sino un profesional que necesita orientación inicial sobre una necesidad de seguridad en obra o mantenimiento.

## Proceso actual que se quiere mejorar

El proceso comercial inicial puede resumirse así:

1. El cliente detecta una necesidad en obra o instalación.
2. Busca información en la web.
3. Contacta mediante formulario, correo o teléfono.
4. El equipo comercial recibe una consulta.
5. Si falta información, debe pedir aclaraciones.
6. Si la consulta es técnica, debe derivarse a personal competente.
7. Se prepara una respuesta o presupuesto.

El punto crítico está en los pasos 3 a 6: muchas consultas iniciales pueden llegar sin datos suficientes para clasificarlas y responder con precisión.

## Pain point principal

El problema a resolver es la **baja calidad o falta de estructura de algunas consultas iniciales**.

Ejemplos habituales:

- “Necesito una barandilla para una cubierta”, sin indicar si es provisional o definitiva.
- “¿Cumple la normativa?”, sin producto, ficha técnica ni contexto.
- “Quiero presupuesto”, sin longitud, ubicación, soporte o urgencia.
- “Necesito casquillos”, sin cantidad, uso ni compatibilidad.
- “Tengo una zona elevada”, sin saber si hace falta protección temporal o permanente.

Estas consultas obligan al equipo comercial a reconstruir el contexto.

## Consecuencias para la empresa

Si la consulta llega incompleta:

- Se retrasa la primera respuesta.
- El equipo comercial invierte más tiempo en aclaraciones.
- Puede perderse información importante.
- Las consultas técnicas pueden mezclarse con solicitudes comerciales.
- El cliente puede no saber qué datos aportar.
- La priorización de oportunidades es más difícil.

## Cómo responde el proyecto al problema

El copiloto comercial actúa antes del formulario tradicional. Su función es guiar al usuario para que la consulta llegue más ordenada:

- Clasifica la familia comercial.
- Pregunta por tipo de obra, soporte, longitud, urgencia y ubicación.
- Recoge nombre, empresa, correo y teléfono.
- Marca revisión técnica cuando procede.
- Genera un resumen para el panel interno.

## Proceso propuesto con el copiloto

1. El cliente entra en la web.
2. El copiloto ofrece opciones iniciales.
3. El cliente elige o escribe su necesidad.
4. El sistema clasifica la consulta.
5. El copiloto formula preguntas útiles.
6. El usuario aporta datos mínimos.
7. Se genera una ficha comercial.
8. La empresa revisa la solicitud en el panel.
9. El equipo comercial o técnico decide el siguiente paso.

## Beneficiarios

### Cliente

- Recibe orientación inicial.
- Entiende qué información aportar.
- No se enfrenta a un formulario frío.
- Evita promesas técnicas no verificadas.

### Equipo comercial

- Recibe solicitudes más estructuradas.
- Puede filtrar por familia, prioridad y estado.
- Tiene un resumen claro.
- Puede preparar mejor la respuesta.

### Equipo técnico

- Recibe marcadas las consultas sensibles.
- Evita que el chatbot confirme aspectos normativos o de cálculo.
- Puede revisar documentación cuando sea necesario.

## Indicador de que el contexto está bien entendido

La demo no se limita a decir “chatbot para atención al cliente”. Está adaptada al contexto industrial de Protecciones Toledo: protección de borde, riesgo de caída, soportes, perforación, fijaciones, cubiertas, obra, documentación técnica y prudencia normativa.
